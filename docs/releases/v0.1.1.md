A small release of **seihai-listserver**: seihai-rc's secure RC list has a real peer, and gservers can warp players to other servers.

## New

- **The RC list over Seihai's secure login (`SEI00001` on id 5).** seihai-rc's `servers --secure-login --server-key KEY` now gets the RC list from this listserver, hidden servers included, without the account or password crossing the wire in the clear. `require_secure_login = true` refuses classic RC logins as well as classic player logins, and failed secure RC logins count towards `login_fail_limit` (#18, #22).
- **Server warps (`SERVERINFO`).** A gserver can ask where a named server is, for one player; the listserver answers with its name, host and port (case-insensitive, hidden servers included), and the gserver passes that on as a server warp. An unknown name gets no answer (#17).

## Changed

- `seihai-core` moved from `v0.0.5` to `v0.0.6`, with the rest of the suite (#21).

## Tested with

- Loopback tests for the secure RC list: hidden servers listed and tagged `U `, a wrong password, the classic RC list refused under `require_secure_login`, and the rate limit.
- seihai-rc itself against this listserver on loopback: the secure RC list with the right key, a wrong password, a wrong pinned key, and the classic RC list. See `docs/lab/2026-11-12-secure-rc-list.md`.
- seihai-rc's own test suite now logs in through this listserver (seihai-rc #35).
- No real Graal client or RC was run for this release.

## Not in this release

- A lab run where a real RC lists a hidden server (#19).

## Download and run

Pick the archive for your system: Linux x86_64, Windows x86_64, macOS Intel (x86_64) or macOS Apple Silicon (aarch64). Each holds the program, `README.md`, the licences and `seihai-listserver.sample.toml`.

```
seihai-listserver sample-config > seihai-listserver.toml   # then edit it
seihai-listserver
```

Upgrading from `v0.1.0` needs no config change. On macOS, the first start may need right-click → Open, because the build is not signed.
