What seihai-listserver main gained since v0.1.0. There is no change for real Graal clients' lists.

## What's new

- **The RC list over Seihai's secure login (`SEI00001`).** seihai-rc asks for the RC list (id 5) over the secure handshake, and the listserver now answers it. The account and password stay sealed, as they already were for Seihai clients' server list (#22).
- **Server warps.** A gserver can ask for another server by name (`SVO_SERVERINFO`, 25). The listserver answers with that server's host and port (`SVI_SERVERINFO`, 18), so the gserver can warp a player there. Hidden servers are included, and an unknown name gets no answer (#17).
- `seihai-core` comes from its own repository, and is now at `v0.1.0` (#21, #26 to #29, #31, #41, #43).
- The README says which tab of a client's server list each `hq_level` shows under. The 3.04 labs need `hq_level = 2` (#42).
- The design for the next gserver-link features (profiles, global guilds, cross-server lists, PMs and buddies) is written up in `docs/design/gserver-text-profiles-guilds.md` (#40). None of it is in this release.
- The release workflow has a `skip_macos` switch for manual runs. macOS is checked on a lab macOS VM, not GitHub's runners (#25).

## Tested with

- Loopback tests for both new answers.
- A lab run on 2026-11-12 with real clients (`docs/lab/2026-11-12-hidden-server.md`, #30). Six gservers were registered, one of them hidden (HQ level 0). A real 2.22 RC listed all six, with its warning icon on the hidden one. Real 2.22 and 2.31 clients listed the other five and not the hidden one.

## Download and run

The same as v0.1.0. Pick the archive for your system: Linux x86_64, Windows x86_64, macOS Intel (x86_64) or macOS Apple Silicon (aarch64).

```
seihai-listserver sample-config > seihai-listserver.toml   # then edit it
seihai-listserver
```

On macOS, the first start may need right-click → Open, because the build is not signed.
